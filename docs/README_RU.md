# FCA / FCEA — запуск системы

**Архитектор системы: Vadym Tsinderhoz. Версия: 1.0.0. Профиль: Research Local.**

Репозиторий называется **FCA**, архитектура и Python-пакет — **FCEA**. Система принимает исходные данные, сохраняет их происхождение, фиксирует исследовательский протокол, выполняет расчёт через проверки G0–G15 и формирует проверяемый архив доказательств.

## Быстрый запуск

Нужны Git и Python 3.11 или новее. Внешние сервисы, платные ключи и установка зависимостей для запуска из репозитория не требуются.

```sh
git clone https://github.com/Vados992/FCA.git
cd FCA
python -m fcea serve
```

Если команда `python` отсутствует, используйте `python3`.

1. Откройте **http://127.0.0.1:8000**.
2. Откройте локальный файл `var/fcea/credentials.local.json` и скопируйте значение `one_time_tokens.analyst`.
3. Вставьте токен в поле входа. Не публикуйте этот файл и токены.
4. Выберите `policy-rct`, нажмите **Load example**, затем **Freeze & run**.
5. Откройте расчёт: видны результат, интервал, область применимости, проверки, альтернативные сценарии и ограничения.
6. **Download proof packet** скачивает ZIP с исходными данными, протоколом, результатами, контрольными суммами и инструкцией воспроизведения.

Интерфейс и технические названия объектов — на английском. Ввод собственных данных доступен через CLI и API; панель предназначена для запуска, просмотра и рецензирования.

## Запуск всех примеров и тестов

```sh
python -m fcea --data-dir var/demo demo --all
python -m fcea --data-dir var/demo verify
python -m unittest discover -s tests -v
python scripts/validate.py --output validation-output
```

Десять сценариев охватывают восемь предметных направлений. Используются полностью синтетические данные. В отчёте проверки отдельно указаны численные результаты, прохождение всех 16 проверок и воспроизведение каждого архива.

## Docker

```sh
docker compose up --build -d
docker compose exec fcea cat /data/credentials.local.json
```

Адрес тот же: http://127.0.0.1:8000. Токен `analyst` находится в выводе второй команды. Данные сохраняются в томе `fcea-data`. Остановка: `docker compose down`. Не добавляйте `-v`, если хотите сохранить исследования.

## Собственное исследование

```sh
python -m fcea example policy-rct --output my-study.json
```

Отредактируйте файл: исходные наблюдения, уникальные ID, описание гипотезы, область применимости, время доступности информации, допущения, контрольные тесты и параметры. Уберите отметку `synthetic`, только если заменили все соответствующие данные реальными. Укажите правовое основание и возможность распространения источника. Для реальных причинных выводов нужны обоснованные допущения и предметная экспертиза.

```sh
python -m fcea --data-dir var/study import my-study.json
python -m fcea --data-dir var/study freeze policy_rct.protocol
python -m fcea --data-dir var/study run policy_rct.protocol --output run.json
```

Если меняли ID протокола, подставьте новый ID. Фиксация `freeze` запрещает подмену параметров и доказательств. Исправления оформляются новыми объектами с `version` и `supersedes`; для повторного исследования создаётся новый протокол. Значение `known_at` означает момент реальной доступности сведений, а не момент их загрузки в систему.

Результат имеет три независимые оси: **execution_state** — завершилось ли выполнение; **scientific_state** — что поддерживает проверка; **validity_state** — соблюдены ли условия применимости. `SUPPORTED` относится к конкретному операционному тесту и указанной области. Это не автоматическое доказательство произвольного текста гипотезы.

## Архив, рецензирование и выпуск

```sh
python -m fcea --data-dir var/study proof export RUN_ID packet.zip
python -m fcea proof verify packet.zip
python -m fcea proof reproduce packet.zip
```

Вместо `RUN_ID` используйте `id` выполненного расчёта. Нужна та же проверенная версия кода. Проверка архива не запускает код из недоверенного ZIP. Если исходные данные запрещено распространять, архив не является самодостаточным для воспроизведения.

Для локального исследовательского процесса предусмотрены отдельные роли аналитика, рецензентов и ответственного за выпуск. Пример команд — в [OPERATIONS.md](OPERATIONS.md). CLI доверяет локальному пользователю ОС; реальное разделение доступа в совместной работе обеспечивается API-токенами и организационными правилами. HMAC выпуска — локальная аутентификация с общим секретом, не публичная цифровая подпись.

## Что реализовано и где границы

Работают хранилище, происхождение данных, типизированные схемы, четыре графа, протоколы, все проверки G0–G15, восемь адаптеров, контрфактические сценарии, контрольные тесты, противоречия, архивы, рецензирование, API, панель, резервное копирование и восстановление. [Карта L0–L24](ARCHITECTURE.md) связывает архитектуру с кодом и объясняет границы реализации.

Это законченная локальная исследовательская реализация. Для промышленной облачной эксплуатации дополнительно нужны выбранная инфраструктура, SSO/MFA, внешнее закрепление журналов, управление ключами, нагрузочная проверка и независимая научная валидация на реальных данных. Встроенные методы намеренно ограничены и описаны в [METHODS.md](METHODS.md): например, климатический адаптер выполняет один регрессионный тест, а физический — проверку гармонического осциллятора.
